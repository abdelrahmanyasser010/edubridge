# ADR-001: Modular Monolith

- الحالة: Accepted؛ عبارة قاعدة البيانات الواحدة أدناه superseded بواسطة ADR-007
- التاريخ: 2026-07-12

## السياق

النظام يضم لوحة إدارة وتطبيق معلم وتطبيق ولي أمر، وتشترك جميعها في بيانات المدرسة والطالب والحضور والدرجات والإشعارات. الفريق يحتاج حدودًا واضحة مع تنفيذ وتسليم بسيطين.

## القرار

نبني Laravel كتطبيق Modular Monolith بقاعدة بيانات واحدة ونشر واحد، مع فصل الكود حسب business domains وعقود واضحة للآثار الجانبية والتكاملات.

## النتائج

- transactions والاستعلامات المشتركة أبسط.
- التشغيل والمراقبة أقل كلفة.
- يلزم enforcement في structure/reviews حتى لا تتحول الوحدات إلى coupling عشوائي.
- يمكن استخراج مجال مستقل لاحقًا عندما تثبت الحاجة بالتحميل أو الملكية أو دورة النشر، وليس توقعًا مسبقًا.

## البدائل المرفوضة الآن

- Monolith بطبقات عامة فقط: يجعل حدود المجال ضعيفة.
- Microservices: يضيف network failures، distributed consistency، ونفقات تشغيل قبل وجود حاجة مثبتة.
