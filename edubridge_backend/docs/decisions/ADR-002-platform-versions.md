# ADR-002: إصدارات المنصة وبيئة التشغيل

- الحالة: Accepted
- التاريخ: 2026-07-12
- Task: DEC-001

## القرار

- Laravel `^13.0`.
- PHP `^8.5` مع Composer 2.
- MySQL 8.4 LTS باستخدام InnoDB و`utf8mb4`.
- Redis 7.x للـcache والqueues والdistributed locks.
- بيئة الإنتاج Linux؛ Windows بيئة تطوير فقط.
- يبدأ الجهاز الحالي بتثبيت PHP وComposer محليًا لأن Docker وWSL غير مهيئين. تبقى الخدمات وعناوين الاتصال معرفة بالـenvironment variables، ولا يعتمد الكود على Windows.

## أسباب القرار

- المشروع جديد، لذلك نختار الإصدارات المدعومة ذات نافذة العمر الأطول بدل بدء مشروع على Laravel 11 المنتهي أمنيًا.
- MySQL 8.4 إصدار LTS مناسب للاستقرار التشغيلي.
- Redis يفصل الأعمال البطيئة والـlocks عن request lifecycle.

## القيود

- `composer.lock` هو الذي يثبت الإصدارات الفعلية القابلة لإعادة البناء.
- CI يعمل على MySQL ولا يعتمد على نجاح SQLite وحده.
- أي package لا يدعم PHP 8.5 أو Laravel 13 لا يخفض المنصة تلقائيًا؛ نبحث بديلًا أولًا، وأي خفض يحتاج ADR.

## دليل فحص الجهاز

بتاريخ القرار: Git متاح، بينما PHP وComposer وMySQL وDocker غير متاحة في `PATH`، ولا توجد WSL distribution مهيأة. تثبيت أدوات التطوير جزء من `FND-001` وليس تغييرًا في إصدارات المنصة.
