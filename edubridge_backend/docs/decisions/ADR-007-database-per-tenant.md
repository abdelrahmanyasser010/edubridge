# ADR-007: قاعدة بيانات مستقلة لكل مدرسة

- الحالة: Accepted
- التاريخ: 2026-07-12
- Task: DEC-002 clarification
- يلغي: ADR-003 في استراتيجية التخزين، ويعدل بند قاعدة البيانات الواحدة في ADR-001

## السياق

المالك أكد أن المنصة ستخدم أكثر من مدرسة، وأن كل مدرسة نظام مستقل لا يتعامل مع بيانات أي مدرسة أخرى. المطلوب عزل أقوى من مجرد `school_id` داخل جداول مشتركة.

## القرار

نستخدم Database-per-Tenant مع codebase ونشر مركزيين:

- قاعدة `central`: تعريف المدارس، domains، حالة الاشتراك، هوية المستخدم العامة، عضويات المدارس، token metadata، ومراجع اتصالات tenant الآمنة.
- قاعدة مستقلة لكل مدرسة: جميع بيانات الطلاب والمعلمين والأكاديميات والحضور والسلوك والدرجات والنقل والمحفظة والمدفوعات والرسائل وaudit.
- storage namespace ومفاتيح cache/locks/queues وإعدادات التكامل تعزل بالـtenant، ويمكن تخصيص bucket/credentials مستقلين للمدرسة عند الحاجة.

## قواعد صارمة

1. request أو job يعمل داخل tenant واحد فقط.
2. لا cross-tenant joins أو foreign keys أو تقارير مجمعة على بيانات المدارس.
3. لا يقبل اسم database أو connection details من العميل.
4. اختيار tenant يسبق model binding ويعتمد على domain/app context + membership موثقة.
5. worker ينظف الاتصال والسياق بعد كل Job حتى عند الاستثناء.
6. platform support access استثنائي، مؤقت، بسبب مكتوب، MFA، وaudit مركزي ومحلي.
7. إنشاء/تعطيل/نسخ احتياطي/استعادة/ترقية مدرسة عمليات مستقلة قابلة للتتبع.

## الهوية

يمكن لنفس الشخص امتلاك عضوية في أكثر من مدرسة، لكن بعد الدخول يختار عضوية نشطة، ويصدر token/session مقيدًا بمدرسة واحدة. تبديل المدرسة يصدر سياقًا/token جديدًا ولا يحتفظ بـEloquent models أو cache من المدرسة السابقة.

## migrations

- central migrations وtenant migrations مساران منفصلان.
- provisioning ينشئ DB/user بصلاحيات أقل ما يمكن، يطبق migrations، seed أساسي، ثم يفعل المدرسة.
- rollout يطبق tenant migrations تدريجيًا، يسجل version لكل مدرسة، ويتوقف/يعزل الفشل بدل ترك حالة مجهولة.

## النسخ الاحتياطي والحذف

- لكل مدرسة backup/restore مستقلان وRPO/RTO قابلان للقياس.
- تعطيل المدرسة يوقف الوصول أولًا؛ الحذف عملية مؤجلة تتطلب retention/approval ولا تسقط DB فورًا.

## النتائج

العزل والاستعادة والتصدير لكل مدرسة أقوى، مقابل تعقيد أعلى في provisioning والمigrations ومراقبة الاتصالات. هذا التعقيد مقبول لأنه يطابق شرط المنتج الصريح، وسيغطى في `FND-004` وrunbooks الإطلاق.
